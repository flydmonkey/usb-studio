## Context

一场分段录制会立刻把 `USB_<stamp>_01.mp4`、`_02`… 写进操作员选的保存位置。片库平铺列出这些文件，可以分享和删除，但不能合成一条。录制规格目前禁止拼接，是为了避免编码过程里做 mux。现在合段只发生在文件已经入库之后。

目标使用：Android 片库里点一场中的任一段，得到一条可播的完整 MP4，原分段还在。

## Goals / Non-Goals

**Goals:**

- 用文件名把同一时间戳的 `_NN` 识别为一场；至少两段才提供「合并本场」。
- 不重编码：拷贝 H.264 / AAC 样本到新文件。
- 原分段保留；合成片进同一保存位置；失败不留半成品。
- 手机、平板、电视片库都能操作。

**Non-Goals:**

- 停录自动拼接、跨场多选、勾掉某段再合。
- iPad 合段、重新编码、FFmpeg、推流、暂停。
- 改录制分段策略或最短 5 分钟档。

## Decisions

### 1. 分组在 Dart，拼接在 Android 原生

- **选择**：`SegmentPolicy` 解析 `USB_<stamp>_<NN>.mp4`。无后缀的 `USB_<stamp>.mp4` 和 `USB_<stamp>_merged.mp4` 不算分段。片库对同一 stamp 且段数 ≥ 2 的任一行显示「合并本场」。插件 `concatSession(uris)` 按 `_NN` 排序后拼接。
- **理由**：列表已经在 Dart；MediaExtractor / MediaMuxer 必须走原生。iPad 不实现该方法，返回明确不支持。
- **备选**：原生扫描分组。片库刷新路径会分叉，测试更难。

### 2. 不重编码 remux

- **选择**：逐段 `MediaExtractor` 读视频（及可选音频）轨道，写入一个 `MediaMuxer`。时间戳按已写入时长平移，使各段首帧接在上一段末尾之后。轨道格式必须与第一段一致，否则失败。
- **理由**：同场同档位编码，格式一致；比 FFmpeg 少体积；比重编码快且不损画质。段间本来就允许短暂缺口，接缝处可能有极短跳点。
- **备选**：FFmpeg concat。APK 明显变大。整场重编码。发热、耗电、耗时。

### 3. 先写缓存再 publish

- **选择**：输出写到 app cache，成功后再走现有 `CaptureSave.publishMovie`（相册 / 影片 / 下载 / 自定义）。失败删除 cache，不改已有 MediaStore / SAF 项。
- **理由**：进程被杀时不会出现半截合成片进片库。
- **备选**：直接往目标 Uri 写。失败或杀进程会留下坏文件。

### 4. 命名与占用

- **选择**：优先 `USB_<stamp>.mp4`（分段录制本来不用这个名字）。若已存在，则 `USB_<stamp>_merged.mp4`；仍占用则 `_merged2` 递增。永不覆盖原分段。
- **理由**：无后缀名表示「整场」；再次合并不覆盖上一份合成片。
- **备选**：每次覆盖合成片。误操作会丢掉上一份。

### 5. 这场还在录则拒绝

- **选择**：`concatSession` 若当前正在录制且 session stamp 与要合的场相同，返回可读错误，不开始写文件。其他场的合并在录制期间允许。
- **理由**：避免读写同一场刚封上的文件。合段是文件 IO，不必停掉另一场的录制。
- **备选**：任何录制进行中都禁止合并。更简单，但锁屏长录时不能整理上一场。

### 6. 界面保持平铺

- **选择**：列表不改成分组。符合条件的行增加「合并本场」（电视可 D-pad 聚焦）。进行中用不可取消的进度提示；完成后刷新列表。
- **理由**：操作员点任一段就能合整场，不用先理解「场」。
- **备选**：一场一行。改动面大，这一期不需要。

## Risks / Trade-offs

- [段间接缝跳点 / 音画轻微不齐] → 接受；规格已允许换段缺口。失败则提示，保留分段。
- [某段损坏或轨道不一致] → 整场失败，删除 cache，原文件不动。
- [磁盘空间约等于再写一场] → 失败文案说明空间不足。
- [自定义目录权限丢失] → 与现有保存失败相同，可读错误，不删分段。
- [电视上长时合并无触控] → 进度必须遥控可见；完成后回到列表。

## Migration Plan

无数据迁移。已有 `USB_<stamp>_NN.mp4` 会立刻出现合并入口。未分段的 `USB_<stamp>.mp4` 不出现该入口。
